# 开发手册

> 本手册面向后续维护者（也包括几个月后回来改代码的你自己）：
> 从零复现环境、理解每个设计决策、知道去哪里改东西。
> 项目当前状态与决策记录见文末「开发日志」。

## 1. 项目是什么

一个**本地化中文知识库问答系统（RAG, Retrieval-Augmented Generation）**：

把一批文档（Markdown / TXT / PDF）切块、向量化入库；用户提问时先检索出最相关的片段，再交给大模型"开卷考试"式地生成带引用的回答。

技术亮点（也是简历要点）：

- 全链路本地 GPU 加速（RTX 4060）：embedding 与重排模型都在本地推理
- 两级检索漏斗：BM25+向量混合召回（RRF 融合）→ 交叉编码器精排
- 系统性评估：18 题人工评测集，Recall@k / MRR / 延迟多指标对照实验
- 无 API 也能跑：未配置 LLM Key 时自动降级为抽取式回答

## 2. 环境复现（从零到能跑）

### 2.1 硬件与系统要求

- NVIDIA GPU（≥6GB 显存）+ 最新驱动；无 GPU 也能跑（自动回退 CPU，速度慢）
- Windows / Linux 均可，磁盘预留 ~12GB

### 2.2 Python 环境（conda）

```bash
# 本机已有 S:\anaconda3（conda 4.10.1）。注意老版 conda 的两个坑：
# ① 缓存损坏会报 JSONDecodeError → rm -rf S:/anaconda3/pkgs/cache 后重试
# ② 开着系统代理模式的 VPN 会报 check_hostname requires server_hostname
#    → 命令前加 no_proxy='*'
no_proxy='*' conda create -n rag python=3.11 -y
```

### 2.3 依赖安装

```bash
# torch GPU 版：PyPI 的 Windows 包是 CPU-only，必须从 pytorch 官方索引装。
# 国内网络用阿里云镜像（官方源 ~0.7MB/s，阿里云 ~2.5MB/s）：
pip install https://mirrors.aliyun.com/pytorch-wheels/cu121/torch-2.5.1%2Bcu121-cp311-cp311-win_amd64.whl

# 其余依赖：
pip install -r requirements.txt
# 注意 faiss-cpu 必须 ≥1.10：1.8 与 numpy≥2 二进制不兼容（import 即崩）
```

验证 GPU：

```bash
python -c "import torch; print(torch.cuda.is_available())"   # 应输出 True
```

### 2.4 模型下载

```bash
python scripts/download_models.py
```

下载三个模型到项目内 `.hf-home/`（见 §4 配置说明）：bge-base-zh-v1.5（默认向量）、bge-small-zh-v1.5（实验对照组）、bge-reranker-base（重排）。

### 2.5 LLM Key 配置（可选但推荐）

```bash
cp .env.example .env   # 然后编辑 .env 填入 LLM_BASE_URL / LLM_MODEL / LLM_API_KEY
```

支持任何 OpenAI 兼容接口：DeepSeek、硅基流动、本地 Ollama（模板里有三套示例）。不配置则运行在抽取式回退模式。

### 2.6 跑起来

```bash
python scripts/ingest.py        # ① 把 data/raw/ 的语料建入索引
python scripts/ask.py "保研对绩点有什么要求？"   # ② 命令行问答
python app/web_ui.py            # ③ Web 界面（http://127.0.0.1:7860）
python scripts/run_experiments.py               # ④ 跑对照实验
pytest tests/ -v                # ⑤ 单元测试
```

## 4. 配置系统

所有可调参数集中在 `src/config.py`（dataclass 结构，模块级单例 `CONFIG`）：

| 配置块 | 关键参数 | 默认值 | 说明 |
| --- | --- | --- | --- |
| ChunkConfig | strategy / chunk_size / overlap | recursive / 400 / 60 | 分块策略与尺寸（字符） |
| RetrievalConfig | dense_k / final_k / use_hybrid / use_rerank | 20 / 5 / on / on | 两级漏斗与消融开关 |
| ModelConfig | embedding_model / reranker_model | bge-base / bge-reranker-base | 本地模型选型 |
| LLMConfig | 从 .env 读取 | 空=抽取式 | 生成端 |

环境变量约定（`config.py` 导入时即生效，**必须早于 transformers 导入**）：

- `HF_HOME` → 项目内 `.hf-home/`（模型缓存不写 C 盘用户目录）
- `HF_ENDPOINT` → hf-mirror.com（国内镜像）
- `NO_PROXY=*` → 本机 VPN 为系统代理模式，Python requests 走注册表代理会握手失败，直连反而通
- `.env` 里的 `LLM_*` → 生成端三要素

## 5. 架构与数据流

详见 [架构设计.md](架构设计.md)。一句话版本：

```
入库：文档 → 清洗分块(3策略) → GPU向量化 → FAISS索引落盘
问答：问题 → 混合召回(向量top20 ∪ BM25top20, RRF融合)
           → 重排(bge-reranner 精排) → top5 → LLM生成(带引用) 
```

## 6. 实验设计

详见 [实验报告.md](实验报告.md)。四组控制变量实验：

- A 组：分块策略（fixed / recursive / sentence）
- B 组：块大小（200 / 400 / 600）
- C 组：检索消融（混合检索 × 重排，2×2）
- D 组：向量模型（bge-small vs bge-base）

指标：HitRate@5 / Recall@5 / MRR@5 / 延迟。相关性判在**来源文档级**（跨策略公平比较的关键设计）。

## 7. 常见问题排查

| 症状 | 原因与解法 |
| --- | --- |
| `import faiss` 报 `_ARRAY_API not found` | faiss-cpu 版本 <1.10 撞上 numpy≥2，`pip install -U faiss-cpu` |
| conda 建环境报 JSONDecodeError | `rm -rf S:/anaconda3/pkgs/cache`（repodata 半截缓存） |
| conda/pip/hf 下载报 `check_hostname` 或连接失败 | VPN 系统代理模式所致，命令前加 `no_proxy='*'`（已内置到 config.py 的是 HF 部分） |
| torch `cuda: False` | 驱动太老或装成 CPU 版；`torch.__version__` 应带 `+cu121` |
| Web 界面首次提问很慢 | 模型懒加载（约 10-20s），之后毫秒级 |
| 抽取式模式 | .env 未配置 LLM 三要素；配置后重启进程 |

- **2026-08-17 启动脚本升级：RAG 服务窗口彻底隐藏（无任务栏项）**
  - 用户追问："脚本那自动生成的 RAG-QA-Server 框可以一起隐藏吗"。
  - 演进（对你机器成立的结论）：
    1. `start /min "RAG-QA-Server" cmd /c "..."` → 只最小化、仍留任务栏项，用户仍嫌有框。
    2. `powershell Start-Process ... -WindowStyle Hidden` → **实测失败**：双击 bat 后 server.log 空白、页面起不来；隐藏把报错也吞了，python 实际未被拉起（cmd 转义 `^>`/`^&` 在该环境未生效）。
    3. **最终方案 `start "" S:\anaconda3\envs\rag\pythonw.exe app\web_ui.py > outputs\server.log 2>&1`**：用 **`pythonw.exe`**（Windows 原生无窗口 Python）直接启动，天生不弹控制台/任务栏项；日志由 cmd 外层 `>` 重定向绑定到子进程句柄，正常落盘。`start ""` 用空标题规避"带引号标题时外层重定向不生效"的 cmd 怪癖。Ollama serve 同批改回 `start /min`（最小化窗口，Ollama 通常已在跑、此分支多不触发）。
  - **更正此前误判**：早先 §8 写"`pythonw` 与 `WScript.Shell` 均被环境拦截"是错的——`S:\anaconda3\envs\rag\pythonw.exe` 确实存在且可运行；之前"pythonw 起不来"的真实原因是 `start "标题" pythonw ... > log` 里带引号标题导致外层 `> file` 重定向失效（日志空 + 看似起不来），并非 pythonw 被拦。用 `start "" pythonw`（无标题）即可正常工作。
  - 停止脚本无需改：`wmic process where "commandline like '%web_ui.py%'"` 仍能按 python 进程命令行命中。
  - 踩坑（2026-08-17 二次修复）：bat 的 `rem` 注释行若含 `>`（如把"重定向"写成 `> 重定向`），cmd 会把 `>` 当重定向符、把其后的中文拆坏，报 `'盘到' is not recognized` 并卡在端口轮询。**结论：`rem` 注释行严禁出现 `>` `<` `|` `&` 等 cmd 特殊字符**；现启动脚本注释已改纯英文、无特殊字符。

- **2026-08-17 启动脚本终极修复：彻底绕开 cmd `start`，改用 Python launcher**
  - 现象（用户再次报错）：双击 bat 后 Windows 弹「Windows 找不到 `\\` 文件」对话框（标题就是 `\\`），让用户点确定；bat 卡在 `[wait]`，页面起不来。
  - 根因：`start "" S:\anaconda3\envs\rag\pythonw.exe ... > outputs\server.log 2>&1` 这条 cmd 行在**你机器**的 Windows 上有边角 bug：外层 `> log 2>&1` 重定向 + 空标题 + GUI 子程序 + 长路径 综合作用下，cmd 解析 `start` 参数时把要打开的"文件"识别成空（于是 Windows shell 收到 `\\` 触发「找不到 UNC」对话框）。之前 dev log 写的"`start "" pythonw ... > log` 即正常"未实测验证，是误判。
  - 解决：**完全不再用 cmd 的 `start`**。
    - 新增 `app/launcher.py`：用 `subprocess.Popen([PYW, app/web_ui.py], creationflags=DETACHED_PROCESS|CREATE_NO_WINDOW)` 拉起 web_ui，**不传** stdout/stderr/stdin（让 web_ui 继承 launcher 的空 std handle，自身 `sys.stdout is None` 触发 web_ui 顶部的日志重定向）。launcher 自己的日志走 `outputs\launcher.log`（用 `print(..., file=_lf)` 显式写文件，**不**依赖 `sys.stdout`，避免 NUL/PIPE 包装副作用）。
    - `app/web_ui.py` 顶部加 stdout/stderr 兜底：`if sys.stdout is None` 时把输出截断式重定向到 `outputs\server.log`（每次启动清空旧日志），写横幅+Gradio 启动行。
    - `启动知识库问答.bat` 改用 `pythonw.exe app\launcher.py` **同步调用**（约 1-2 秒 launcher 退出，bat 继续端口轮询）。不传 `> log`，不调 `start`，不弹 `\\` 对话框。
    - ollama 启动行加 `if exist` 守护（路径不存在时优雅跳过，不弹错）。
  - 日志分工：
    - `outputs\launcher.log`：launcher 启动横幅 + 拉起 web_ui 的 PID + launcher 自身异常。
    - `outputs\server.log`：web_ui 启动横幅 + Gradio/uvicorn 输出 + 问答回调异常。
  - 验证（managed dev，模拟 bat 调 pythonw，DEVNULL 避免 PIPE 副作用）：PORT UP after 5s；launcher.log 198 字节（3 行横幅）；server.log 196 字节（web_ui 横幅 + Gradio URL）。bat 场景下无 `\\` 弹窗（cmd `start` 完全不参与）。
  - 关键认知：cmd `start "" GUI.exe ... > log 2>&1` 的外层重定向在 Windows 上**对 GUI 子程序不可靠**——既捕获不到 stdout（GUI 无控制台），又可能让 `start` 解析出空路径弹「找不到」对话框。**隐藏启动 GUI 程序的最稳方案**是：用 Python launcher + `DETACHED_PROCESS` + 子程序自管日志，**让 cmd 只做 `pythonw.exe launcher.py` 同步调用**。
