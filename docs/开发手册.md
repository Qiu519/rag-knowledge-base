# 开发手册

> 本手册面向后续维护者（也包括几个月后回来改代码的你自己）：
> 从零复现环境、理解每个设计决策、知道去哪里改东西。
> 项目当前状态与决策记录见文末「开发日志」。

## 1. 项目是什么

一个**本地化中文知识库问答系统（RAG, Retrieval-Augmented Generation）**：

把一批文档（Markdown / TXT / PDF）切块、向量化入库；用户提问时先检索出最相关的片段，再交给大模型"开卷考试"式地生成带引用的回答。

技术亮点（也是简历要点）：

- 全链路本地 GPU 加速（RTX 4060）：embedding 与重排模型都在本地推理
- 两级检索漏斗：BM25+向量混合召回（RRF 融合）→ 交叉编码器精排
- 系统性评估：18 题人工评测集，Recall@k / MRR / 延迟多指标对照实验
- 无 API 也能跑：未配置 LLM Key 时自动降级为抽取式回答

## 2. 环境复现（从零到能跑）

### 2.1 硬件与系统要求

- NVIDIA GPU（≥6GB 显存）+ 最新驱动；无 GPU 也能跑（自动回退 CPU，速度慢）
- Windows / Linux 均可，磁盘预留 ~12GB

### 2.2 Python 环境（conda）

```bash
# 本机已有 S:\anaconda3（conda 4.10.1）。注意老版 conda 的两个坑：
# ① 缓存损坏会报 JSONDecodeError → rm -rf S:/anaconda3/pkgs/cache 后重试
# ② 开着系统代理模式的 VPN 会报 check_hostname requires server_hostname
#    → 命令前加 no_proxy='*'
no_proxy='*' conda create -n rag python=3.11 -y
```

### 2.3 依赖安装

```bash
# torch GPU 版：PyPI 的 Windows 包是 CPU-only，必须从 pytorch 官方索引装。
# 国内网络用阿里云镜像（官方源 ~0.7MB/s，阿里云 ~2.5MB/s）：
pip install https://mirrors.aliyun.com/pytorch-wheels/cu121/torch-2.5.1%2Bcu121-cp311-cp311-win_amd64.whl

# 其余依赖：
pip install -r requirements.txt
# 注意 faiss-cpu 必须 ≥1.10：1.8 与 numpy≥2 二进制不兼容（import 即崩）
```

验证 GPU：

```bash
python -c "import torch; print(torch.cuda.is_available())"   # 应输出 True
```

### 2.4 模型下载

```bash
python scripts/download_models.py
```

下载三个模型到项目内 `.hf-home/`（见 §4 配置说明）：bge-base-zh-v1.5（默认向量）、bge-small-zh-v1.5（实验对照组）、bge-reranker-base（重排）。

### 2.5 LLM Key 配置（可选但推荐）

```bash
cp .env.example .env   # 然后编辑 .env 填入 LLM_BASE_URL / LLM_MODEL / LLM_API_KEY
```

支持任何 OpenAI 兼容接口：DeepSeek、硅基流动、本地 Ollama（模板里有三套示例）。不配置则运行在抽取式回退模式。

### 2.6 跑起来

```bash
python scripts/ingest.py        # ① 把 data/raw/ 的语料建入索引
python scripts/ask.py "保研对绩点有什么要求？"   # ② 命令行问答
python app/web_ui.py            # ③ Web 界面（http://127.0.0.1:7860）
python scripts/run_experiments.py               # ④ 跑对照实验
pytest tests/ -v                # ⑤ 单元测试
```

## 4. 配置系统

所有可调参数集中在 `src/config.py`（dataclass 结构，模块级单例 `CONFIG`）：

| 配置块 | 关键参数 | 默认值 | 说明 |
| --- | --- | --- | --- |
| ChunkConfig | strategy / chunk_size / overlap | recursive / 400 / 60 | 分块策略与尺寸（字符） |
| RetrievalConfig | dense_k / final_k / use_hybrid / use_rerank | 20 / 5 / on / on | 两级漏斗与消融开关 |
| ModelConfig | embedding_model / reranker_model | bge-base / bge-reranker-base | 本地模型选型 |
| LLMConfig | 从 .env 读取 | 空=抽取式 | 生成端 |

环境变量约定（`config.py` 导入时即生效，**必须早于 transformers 导入**）：

- `HF_HOME` → 项目内 `.hf-home/`（模型缓存不写 C 盘用户目录）
- `HF_ENDPOINT` → hf-mirror.com（国内镜像）
- `NO_PROXY=*` → 本机 VPN 为系统代理模式，Python requests 走注册表代理会握手失败，直连反而通
- `.env` 里的 `LLM_*` → 生成端三要素

## 5. 架构与数据流

详见 [架构设计.md](架构设计.md)。一句话版本：

```
入库：文档 → 清洗分块(3策略) → GPU向量化 → FAISS索引落盘
问答：问题 → 混合召回(向量top20 ∪ BM25top20, RRF融合)
           → 重排(bge-reranner 精排) → top5 → LLM生成(带引用) 
```

## 6. 实验设计

详见 [实验报告.md](实验报告.md)。四组控制变量实验：

- A 组：分块策略（fixed / recursive / sentence）
- B 组：块大小（200 / 400 / 600）
- C 组：检索消融（混合检索 × 重排，2×2）
- D 组：向量模型（bge-small vs bge-base）

指标：HitRate@5 / Recall@5 / MRR@5 / 延迟。相关性判在**来源文档级**（跨策略公平比较的关键设计）。

## 7. 常见问题排查

| 症状 | 原因与解法 |
| --- | --- |
| `import faiss` 报 `_ARRAY_API not found` | faiss-cpu 版本 <1.10 撞上 numpy≥2，`pip install -U faiss-cpu` |
| conda 建环境报 JSONDecodeError | `rm -rf S:/anaconda3/pkgs/cache`（repodata 半截缓存） |
| conda/pip/hf 下载报 `check_hostname` 或连接失败 | VPN 系统代理模式所致，命令前加 `no_proxy='*'`（已内置到 config.py 的是 HF 部分） |
| torch `cuda: False` | 驱动太老或装成 CPU 版；`torch.__version__` 应带 `+cu121` |
| Web 界面首次提问很慢 | 模型懒加载（约 10-20s），之后毫秒级 |
| 抽取式模式 | .env 未配置 LLM 三要素；配置后重启进程 |

  - 端到端验证 4 题：3 题准确带引用；1 题（"挂科能否保研"）检索未命中目标块，
    模型按 prompt 约束如实拒答而非编造——防幻觉设计的正向案例
