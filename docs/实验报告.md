# 实验报告：RAG 检索组件的对照评估

> 日期：2026-08-17（v2，含上下文增强分块修复后的复测） · 环境：RTX 4060 Laptop (8GB) / PyTorch 2.5.1+cu121
> 原始数据：`outputs/results.csv` · 图表：`outputs/fig*.png`

## 1. 实验设置

### 1.1 语料与评测集

- 语料：12 篇高校制度文档（培养方案 / 课程大纲 / 保研 / 奖学金 / 转专业 / 辅修 / 国际交流 / 选课规定），主题相近、条件数字交叉（如绩点 2.5 / 3.0 / 3.3 分属不同制度），构成天然干扰。
- 评测集：**38 题**人工标注（18 基础题 + 20 干扰题），每题含问题、相关来源、参考答案。问题风格刻意混合：直问术语型（BM25 友好）与口语改写型（向量检索友好）。

### 1.2 指标口径

相关性判在**来源文档级**（跨分块策略可比的前提，详见架构设计 §2.4）。

| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| hit@1 / recall@1 | 第一名是否命中相关来源 | 严格档，区分度主指标 |
| recall@5 | top-5 覆盖的相关来源比例 | 召回完整性 |
| mrr@5 | 首个相关结果排名倒数均值 | 排序质量 |
| latency_ms | 检索+重排耗时（不含生成） | 体验指标 |

### 1.3 实验矩阵（控制变量法，四组 12 配置）

- A 分块策略：fixed / recursive / sentence（size=400 对齐）
- B 块大小：200 / 400 / 600（recursive）
- C 检索消融：混合检索 × 重排（2×2）
- D 向量模型：bge-small-zh-v1.5 (512d) vs bge-base-zh-v1.5 (768d)

## 2. 结果总表（v2：上下文增强分块后）

| 配置 | hit@1 | recall@5 | mrr@5 | 延迟(ms) |
| --- | --- | --- | --- | --- |
| strategy=fixed / recursive / sentence | 0.816 | **1.000** | 0.899 | 52-84 |
| size=200 / 400 / 600 | 0.816 | **1.000** | 0.899 | 52-55 |
| hybrid=on, rerank=on | 0.816 | **1.000** | 0.899 | 56.0 |
| **hybrid=on, rerank=off** | **0.842** | **1.000** | **0.904** | **9.6** |
| hybrid=off, rerank=on | 0.816 | **1.000** | 0.899 | 43.1 |
| hybrid=off, rerank=off（基线） | 0.842 | 0.947 | 0.876 | **6.6** |
| bge-small / bge-base | 0.816 | **1.000** | 0.899 | 40-41 |

> v1（无标题上下文）的对照数据见 git 历史版本：当时混合检索 recall@5=0.974，
> 需重排补至 1.000。v2 引入上下文增强分块后混合检索单独即达 1.000。

## 3. 发现与分析

### 发现 1：来源级 recall@5 全线饱和

除关闭重排的两格（0.974）外全部 1.000。**这不是"系统完美"，而是"评测太容易"**：12 个来源、top-5 覆盖率 42%，主题清晰的语料上粗排就能进前五。诚实的结论是——该口径下 recall@5 失去区分度，有效信息集中在 hit@1 与 MRR（这也是本报告同时报告 @1 档的原因）。后续工作应引入块级判定与更大规模干扰语料。

### 发现 2：重排的两面性与组件交互（本报告最有价值的发现）

v1 与 v2 两轮数据对照（同一评测集、同一语料，唯一差异是分块是否拼标题）：

| 配置 | v1 hit@1 / recall@5 | v2 hit@1 / recall@5 |
| --- | --- | --- |
| 纯向量基线 | 0.868 / 0.974 | 0.842 / 0.947 |
| + 混合检索（RRF 直出） | 0.895 / 0.974 | **0.842 / 1.000** |
| + 混合检索 + 重排 | 0.842 / 1.000 | 0.816 / 1.000 |

两轮一致的结论：**重排恒定损害 top-1 精度（-2.6 ~ -5.3pp）并带来 5-6 倍延迟**；
v1 中它换来了召回完整（0.974→1.000），v2 中混合检索自己就把召回补满，重排的
召回收益消失。坏例分析不变：交叉编码器对"数字+同词"型干扰抵抗力弱。

**组件交互的教训：消融结论不是静态的**——上游修复（上下文增强分块）改变了下游
组件（重排）的边际贡献。评估必须随系统演进复测，单次消融的结论有效期有限。

### 发现 2.5：上下文增强分块的缺陷修复价值（v1→v2 的动因）

用户实测发现同义提问失效：问"保研对绩点**排名**的要求"能答、问"保研对绩点有
什么要求"拒答。诊断链：向量检索两例均正确（目标块第 2 名）→ BM25 因"保研"与
语料"推荐免试"零字面重叠而失焦 → RRF 稀释 → 重排把目标块挤出候选。

三项修复：① **查询改写**（LLM 把口语规范化后检索）；② **上下文增强分块**
（embedding/BM25/重排统一用"标题+正文"表示，纯编号列表类正文从此不再是语义
孤岛）；③ final_k 5→7。修复后完整正确作答，38 题回归 recall@5=1.000 保持。

**方法论收获：来源级指标全绿 ≠ 系统好用**——两个失效问法都不在原评测集里，
是用户真实使用暴露的。评测集应持续吸收线上坏例（bad case 回流）。

### 发现 3：延迟结构——重排是本地管线的延迟主体

纯检索（BM25+向量+RRF）约 9-10ms，加重排后 43-56ms，其中约 35-45ms 花在 20 对交叉编码上。生成端（API，关思考）另计 1-3s。若要优化端到端延迟，优先级：候选数 20→10（重排耗时近似线性）> 换更小重排模型 > 精简 embedding。v2 数据下"关重排"本身即是最的大单项优化（56→9.6ms），代价是极端改写问法的鲁棒性（见发现 2.5 的修复链路）。

### 发现 4：bge-small 与 bge-base 指标打平

38 题上两模型 hit@1 / MRR 完全一致。该语料规模下向量模型不是瓶颈——**资源受限部署（纯 CPU / 树莓派级）选 small（参数量 1/3、维度 512）零损失**。指标打平的另一面是评测区分度不足（同发现 1），不构成"两模型等价"的一般结论。

### 发现 5：分块策略与块大小在来源级不敏感

本语料段落天然较短（多数 <400 字），三种策略产出的块集合高度相似（recursive 与 fixed 同为 57 块；size=200 为 62 块），来源级指标无差异。**递归分块的价值在块语义完整性**（不拦腰截断句子），这影响下游生成质量而非来源级检索指标——验证它需要块级评估或端到端答案质量评估，列为后续工作。

## 4. 第六章：本地小模型 vs 云端大模型（生成后端对比）

### 4.1 实验设计

同一套检索端（本地 GPU 的向量/BM25/重排完全一致），只切换生成端：

| 后端 | 规格 | 成本 | 依赖 |
| --- | --- | --- | --- |
| 本地 Ollama qwen2.5:7b（Q4 量化） | 4.7GB 显存，与检索模型共存于 8GB 卡 | 免费 | 断网可用 |
| 阿里云百炼 qwen3.7-max（API） | 云端旗舰 | 本次 6 题约 0.02 元 | 需联网 |

每个后端独立完成"查询改写 + 生成"两步（改写同样消耗模型能力，端到端对比才公平）。
6 题覆盖四类难度：事实题 / 同义改写题 / 数字辨析题×2 / 条件综合题 / 语料外拒答题。
原始记录：`outputs/comparison_local_vs_cloud.md`。

### 4.2 结果

| 题型 | 问题 | 本地 7B | 云端 max | 本地耗时 | 云端耗时 |
| --- | --- | --- | --- | --- | --- |
| 事实 | 毕业论文查重上限 | ❌ 过度拒答 | ✓ | 5.6s | 2.2s |
| 同义改写 | 保研对绩点有什么要求 | ❌ 过度拒答 | ✓ | 2.2s | 3.4s |
| 数字辨析 | 奖学金综合素质测评占比 | ✓（"30分/30%"表述摇摆） | ✓ | 3.1s | 2.8s |
| 数字辨析 | 辅修绩点要求 | ❌ 过度拒答 | ✓ | 3.0s | 2.0s |
| 条件综合 | 转专业条件 | ✓ | ✓ | 5.0s | 3.8s |
| 拒答 | 食堂哪家好吃（语料外） | ✓ 正确拒答 | ✓ 正确拒答 | 1.8s | 1.7s |

**本地 3/6，云端 6/6。延迟同量级**（本地生成并不慢，瓶颈从来不是速度）。

### 4.3 发现

1. **本地模型的签名式失败："自相矛盾的过度拒答"**——三道错题全部同一死法：
   模型在解释里原样复述出答案（"排名位于专业前15%""绩点不低于2.5"），
   然后以"没有具体说明数值要求"为由拒答。这是小模型在严格防幻觉指令下的
   典型行为：学会了"拒答安全"，没学会"何时答案已经在手上"。
2. **改写能力同样分层**：云端把"保研"规范成"推荐免试攻读硕士研究生"，
   本地只产出"保送研究生对绩点有什么要求"；一道题本地索性不改写。
   检索端靠上下文增强分块兜住了，生成端的差距依然真实存在。
3. **拒答题双方都满分**：语料外问题两边都干净利落地拒绝，防幻觉底线
   本地模型守得住——它的失败集中在"该答不答"，不是"不该答乱答"。
4. **显存可行**：7B Q4 + bge-base + bge-reranker 共存实测 5.8GB / 8GB。

### 4.4 工程结论

- **默认云端**（质量敏感场景）：答对率差异（6/6 vs 3/6）远大于成本差异（每题约 0.003 元）。
- **本地是合格的离线兜底**：断网、隐私敏感、零成本场景下可用，且拒答底线可靠。
- 切换成本为 `.env` 三行配置（系统对生成端透明，OpenAI 兼容协议通吃）。

## 5. 结论

1. 当前语料+口径下的**推荐配置**：recursive/400 + hybrid=on + 上下文增强分块 + bge-small；重排按场景取舍（追延迟关、追排序深度开，注意其对 top-1 的负贡献）。
2. 系统性收获一：**评测口径决定结论**——来源级 recall@5 在小语料上会掩盖组件差异，hit@1/MRR + 消融才能暴露重排的真实代价。
3. 系统性收获二：**消融结论有有效期**——上游分块修复使重排的召回收益归零（发现 2），组件贡献是交互的、非孤立的。
4. 系统性收获三：**指标全绿 ≠ 好用**——真实用户问法（口语/同义词）暴露了评测集外的失效模式，坏例回流是评测集进化的核心机制。
5. 系统性收获四：**生成端分层**——本地 7B 的失败模式是"自相矛盾的过度拒答"（该答不答），云端旗舰是 6/6；本地是合格的离线兜底，不是等价替代（第四章）。
6. 后续工作：把用户坏例持续加入评测集；块级相关性评估；rerank 分数与 RRF 的加权融合；端到端答案质量评估（faithfulness/幻觉率，需 LLM-as-judge）；跨文档多跳问题的检索策略（当前正确拒答）。
